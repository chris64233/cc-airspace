# cc-airspace

管理无人机飞行申请、航段与空域时隙。

## 开发环境

- JDK 21
- Spring Boot 4.1.1
- Maven Wrapper 3.9.9
- H2

## 本地运行

启动服务：

    ./mvnw spring-boot:run

运行测试：

    ./mvnw clean test

## 核心概念

- **航段（AirSegment）**：空域资源，带高度范围 `[minAltitude, maxAltitude]` 与容量 `capacity`。
- **许可（FlightClearance）**：一次飞行申请，持有有序航段占用（SegmentReservation），
  状态机为 `ACTIVE -> CANCELLED / COMPLETED`。
- **航线版本（RouteVersion）**：许可的完整航线快照。初始提交为版本 1，每次改道追加一个版本，
  历史版本全部保留。
- **占用事件（SegmentOccupancyEvent）**：逐航段的 `ACQUIRE` / `RELEASE` 审计轨迹，
  提交、改道、取消时按发生顺序记录。
- **关闭事件（AirspaceClosure）**：临时空域关闭，指定一组航段（区域）与关闭时段
  `[startTime, endTime)`，状态机为 `ACTIVE -> CANCELLED`，持有范围版本 `scopeVersion`。
- **关闭影响标记（ClosureImpact）**：关闭事件对单个航班单个航段的影响记录，
  状态为 `PENDING / HANDLED / RELEASED / EXPIRED`，并冻结识别时的航线版本与已飞航段数快照。

## 改道（Reroute）

改道申请 `RerouteRequest` 引用现有许可，包含：

| 字段 | 含义 |
| --- | --- |
| `rerouteNo` | 改道业务号（幂等键，全局唯一） |
| `expectedVersion` | 申请基于的许可版本，与当前版本不一致则拒绝 |
| `fromLegIndex` | 改道起点航段序号，新航线 = 当前航线 `[0, fromLegIndex)` 前缀 + `legs` |
| `effectiveAt` | 新航线生效时间，容量判定区间为 `[effectiveAt, 许可结束时间)` |
| `legs` | 替换尾部的有序新航段（航段代码 + 高度） |

语义与约束：

1. **衔接位置**：`fromLegIndex` 不得小于许可当前已飞过航段数（`flownLegCount`），
   已飞过的航段不可改写；保留前缀与新航段不得重复。
2. **原子换容量**：事务内先按主键升序一次性锁定全部新旧航段，逐段判定高度范围与容量
   （排除本许可自身占用），全部满足后才换线——先取得全部新航段容量，再释放不再使用的旧航段。
   任一航段容量不足或许可版本已变化，整个事务回滚，原许可与原占用保持不变。
3. **并发安全**：改道、取消、飞行开始、位置上报都先取许可行写锁串行化；
   已取消（`CANCELLED`）或已完成（`COMPLETED`）的许可不能改道；
   基于旧版本或旧位置的请求直接拒绝，不会释放当前仍需要的容量。
4. **幂等**：相同 `rerouteNo` + 相同内容返回首次结果（`created=false`）；
   相同 `rerouteNo` + 不同内容抛幂等冲突。数据库唯一约束兜底并发重复。

## 飞行进度

- `start(externalNo)`：标记飞行开始（幂等）。
- `reportProgress(externalNo, flownLegCount)`：推进已飞过航段数；基于旧位置的上报被忽略，
  不会回退；飞完全部航段后许可自动置为 `COMPLETED`。

## 查询能力

- `get(externalNo)`：当前有效航线（含版本号、已飞航段数、逐航段占用数）。
- `routeHistory(externalNo)`：全部航线历史版本（含每次改道前后的完整航线）。
- `occupancyEvents(externalNo)`：逐航段占用事件流（ACQUIRE / RELEASE，含版本与改道业务号）。
- `conflicts(externalNo)`：当前航线中时间窗内其他有效许可占用数已达到容量的冲突航段。

## 临时空域关闭（Closure）

关闭事件 `ClosureRequest` 指定区域（航段代码集合）与时段，创建后立即识别受影响航班：

| 字段 | 含义 |
| --- | --- |
| `eventNo` | 关闭事件业务号（幂等键，全局唯一） |
| `startTime` / `endTime` | 关闭时段，左闭右开；只影响时间窗重叠的航班 |
| `segmentCodes` | 关闭区域航段集合；关闭时段内这些航段不得被新航线使用 |
| `scopeVersion` | 范围版本，创建为 1，每次范围调整 +1 |

### 受影响航段识别

只标记**尚未进入关闭区域**的航段：在关闭时段内使用关闭航段、且航段序号不小于当前已飞
航段数（`flownLegCount`）的 ACTIVE 航班产生 `PENDING` 标记；已进入或已飞完的航段不标记，
不能反向修改；已取消 / 已完成航班不标记。标记冻结识别时的航线版本与已飞航段数快照。

### 关闭改道 `ClosureRerouteRequest`

针对某关闭事件为指定航班确认替代航线，字段含义与普通改道一致，另含：

| 字段 | 含义 |
| --- | --- |
| `expectedScopeVersion` | 申请基于的关闭范围版本，与当前版本不一致则拒绝 |
| `expectedClearanceVersion` | 申请基于的许可航线版本，不一致则拒绝 |
| `fromLegIndex` | 可空，默认取该航班最早的待处理受影响航段；显式给出时不得晚于该航段 |

语义与约束：

1. **旧方案拒绝**：关闭范围版本（范围 / 时段调整后 +1）、许可航线版本或航班状态
   （已取消 / 已完成）任一变化，确认时直接拒绝；关闭已取消后也不能再确认。
2. **必须避开**：替代航线的未飞航段不得再次进入该关闭在关闭时段覆盖的航段，
   起点晚于最早受影响航段同样拒绝。
3. **原子换容量**：在同一事务内先取得全部新航段容量、再释放不再使用的旧航段，
   并把该关闭对应的待处理标记全部置为 `HANDLED`（记录改道业务号与生效版本）。
   任一容量、关闭、版本校验失败整体回滚，原航线与原占用保持不变。
4. **运行记录保留**：初始与每次改道的航线版本、逐航段 ACQUIRE / RELEASE 事件、
   已 `HANDLED` / `EXPIRED` 的标记全部保留，不因后续关闭取消而删除。
5. **飞行进度联动**：位置上报推进后，航班已进入的待处理标记置为 `EXPIRED`，
   后续关闭改道只能处理剩余未飞航段。
6. **普通改道联动**：普通改道后若未飞航线仍穿越任一关闭区域则拒绝
   （`CLOSURE_CONFLICT`）；主动避开的，相关待处理标记同步置为 `HANDLED`。
   提交新申请同样不得经过生效中的关闭航段。
7. **并发安全**：加锁顺序统一为 关闭事件 -> 许可（主键升序）-> 航段（主键升序）
   -> 待处理标记，避免死锁；并发关闭改道继续逐段判定容量，只成功满足容量的请求。

### 取消关闭与范围调整

- **取消关闭**：只把尚未处理航班的 `PENDING` 标记置为 `RELEASED`、区域重新开放；
  **不自动撤销已完成的改道**（航线、容量占用、历史版本与事件均保留）。重复取消幂等。
- **范围调整 `reschedule`**：替换区域航段 / 时段并使 `scopeVersion` +1。
  已 `HANDLED` 的标记保留；`PENDING` 标记按新范围重算——移出范围置 `RELEASED`，
  航班已进入置 `EXPIRED`，仍受影响则刷新快照，新增受影响航段补建标记。
  调整前下发但未确认的旧方案因范围版本过期被拒绝。

### 关闭查询

- `closureService.get(eventNo)` / `list()`：关闭事件（含状态、范围版本、各状态标记计数）。
- `closureService.impacts(eventNo)`：关闭事件下受影响航班与逐航段处理结果。
- `closureService.impactsOfFlight(externalNo)`：某航班跨关闭事件的全部影响标记。

时的回滚不变性、已取消与已完成许可的改道拒绝、已飞航段保护与旧位置请求不释放容量、
高度与生效时间校验、历史版本与占用事件记录、冲突航段查询，以及并发改道只成功一次、
改道与取消并发下最终状态一致。

`ClosureServiceTests` 覆盖：关闭只识别时间窗重叠且尚未进入的航段、已进入航段过期不可
反向修改、关闭改道同事务切换容量并保留运行记录、替代航线仍穿越关闭区域 / 关闭范围版本
过期 / 许可版本过期 / 起点晚于受影响航段时的旧方案拒绝、普通改道与提交的关闭冲突、
取消关闭只解除未处理航班而不撤销已完成改道、范围调整后标记重算、关闭创建与关闭改道幂等、
关闭事件 / 受影响航班 / 结果查询，以及并发关闭改道只有一班成功、替代航段容量不足时一班
回滚保持原占用、关闭改道与取消并发下无悬空待处理标记。
