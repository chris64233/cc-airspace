# cc-airspace

管理无人机飞行申请、航段与空域时隙，支持临时空域关闭与受影响航班的改道协调。

## 开发环境

- JDK 21
- Spring Boot 4.1.1
- Maven Wrapper 3.9.9
- H2

## 本地运行

启动服务：

    ./mvnw spring-boot:run

运行测试：

    ./mvnw clean test

## 核心概念

- **航段（AirSegment）**：空域资源，带高度范围 `[minAltitude, maxAltitude]` 与容量 `capacity`。
- **许可（FlightClearance）**：一次飞行申请，持有有序航段占用（SegmentReservation），
  状态机为 `ACTIVE -> CANCELLED / COMPLETED`。
- **航线版本（RouteVersion）**：许可的完整航线快照。初始提交为版本 1，每次改道追加一个版本，
  历史版本全部保留；由空域关闭驱动的改道还记录 `closureNo` 与关闭范围版本。
- **占用事件（SegmentOccupancyEvent）**：逐航段的 `ACQUIRE` / `RELEASE` 审计轨迹，
  提交、改道、取消时按发生顺序记录。
- **关闭事件（AirspaceClosure）**：临时空域关闭，指定一组航段构成的区域与
  `[startTime, endTime)` 时段，状态为 `ACTIVE / CANCELLED`，带范围版本 `scopeVersion`。
- **关闭影响标记（ClosureImpact）**：关闭事件对「航班 × 受影响航段」的标记，
  状态为 `PENDING`（尚可调整）/ `REROUTED`（已确认替代航线）。

## 改道（Reroute）

改道申请 `RerouteRequest` 引用现有许可，包含：

| 字段 | 含义 |
| --- | --- |
| `rerouteNo` | 改道业务号（幂等键，全局唯一） |
| `expectedVersion` | 申请基于的许可版本，与当前版本不一致则拒绝 |
| `fromLegIndex` | 改道起点航段序号，新航线 = 当前航线 `[0, fromLegIndex)` 前缀 + `legs` |
| `effectiveAt` | 新航线生效时间，容量判定区间为 `[effectiveAt, 许可结束时间)` |
| `legs` | 替换尾部的有序新航段（航段代码 + 高度） |
| `closureNo` / `expectedClosureVersion` | 可选，响应某个空域关闭事件时携带 |

语义与约束：

1. **衔接位置**：`fromLegIndex` 不得小于许可当前已飞过航段数（`flownLegCount`），
   已飞过的航段不可改写；保留前缀与新航段不得重复。
2. **原子换容量**：事务内先按主键升序一次性锁定全部新旧航段，逐段判定高度范围与容量
   （排除本许可自身占用），全部满足后才换线——先取得全部新航段容量，再释放不再使用的旧航段。
   任一航段容量不足或许可版本已变化，整个事务回滚，原许可与原占用保持不变。
3. **并发安全**：改道、取消、飞行开始、位置上报都先取许可行写锁串行化；
   已取消（`CANCELLED`）或已完成（`COMPLETED`）的许可不能改道；
   基于旧版本或旧位置的请求直接拒绝，不会释放当前仍需要的容量。
4. **幂等**：相同 `rerouteNo` + 相同内容（含关闭事件引用）返回首次结果（`created=false`）；
   相同 `rerouteNo` + 不同内容抛幂等冲突。数据库唯一约束兜底并发重复。

## 临时空域关闭（Closure）

创建关闭事件 `CreateClosureRequest`（`closureNo` 幂等、`reason`、`startTime` / `endTime`、
`segmentCodes` 区域），还可用 `ReviseClosureRequest` 修订区域 / 时段、用 `cancel` 取消。

### 受影响航段的识别与保护

1. 创建 / 修订关闭事件时，在事务内锁定区域航段并扫描时间窗重叠的有效许可：
   只标记许可**尚未进入**的航段（航段序号 `>= flownLegCount`）。
   已进入或已飞完的航段不标记，之后也**不能反向修改**。
2. 标记携带标记时刻的关闭范围版本（`scopeVersionAtMark`）。
3. 航班位置上报飞入某航段后，该航段及其之前的 PENDING 标记随之解除（既成运行事实）；
   许可取消 / 完成时其余 PENDING 标记一并丢弃。已 REROUTED 的记录始终保留。

### 确认替代航线：容量与关闭同事务处理

- 引用关闭事件的改道在**同一事务**内完成：校验通过 → 取得全部新航段容量 →
  释放旧航段容量 → 写入新航线版本 → 把对应 PENDING 标记置为 `REROUTED`
  （记录处理改道号）。任一步失败整体回滚。
- **拒绝旧方案**：以下任一变化都会让方案失效并抛状态冲突：
  - 关闭范围 / 时段被修订（`scopeVersion` 与 `expectedClosureVersion` 不一致）；
  - 关闭事件已取消；
  - 许可航线版本已变化（`expectedVersion` 过期）或状态已变为取消 / 完成；
  - 航班已不再有该关闭事件的 PENDING 标记（已被处理或限制已解除）；
  - 替代航线仍穿越任何有效关闭区域（保留前缀中只校验尚未飞入的航段）。
- **提交与普通改道同样受限**：任何最终穿越有效关闭时段 / 区域的放行或改道都会被拒绝。
  因此关闭期间航段容量即便空闲也不会被重新订入；关闭取消后自动恢复。

### 修订与取消

- **修订**：范围版本 +1，删除全部 PENDING 标记并按新范围重扫重标；
  已 REROUTED 的运行记录保留，已完成的改道不会被撤销或重算。
- **取消关闭**：只删除 PENDING 标记（解除尚未处理航班的限制），
  **不自动撤销已完成的改道**；航段恢复可订。重复取消幂等。

### 并发与加锁

全局加锁层次，所有事务严格按此顺序、同层按主键升序加锁，避免死锁：

```
关闭事件行(level0) -> 航段行(level1) -> 许可行(level2) -> 占用/影响标记(level3)
```

- 并发改道继续在容量行锁下判定，替代航段容量不足时只有一个事务成功（见测试）。
- 改道与关闭创建 / 修订 / 取消并发时由上述锁序串行化；加锁前的探测只读标量，
  持锁后重读最新状态，杜绝一级缓存读到旧值。
- 影响标记是创建 / 修订时刻的识别结果；航班在关闭创建的同时并发完成绕飞时，
  标记可能短暂滞后，会在下次改道确认、航班取消 / 完成或关闭取消时自动对齐。

## 飞行进度

- `start(externalNo)`：标记飞行开始（幂等）。
- `reportProgress(externalNo, flownLegCount)`：推进已飞过航段数；基于旧位置的上报被忽略，
  不会回退；飞入关闭区域属既成事实，相应 PENDING 标记解除；
  飞完全部航段后许可自动置为 `COMPLETED`。

## 查询能力

许可：

- `get(externalNo)`：当前有效航线（含版本号、已飞航段数、逐航段占用数）。
- `routeHistory(externalNo)`：全部航线历史版本（含关闭事件号与范围版本）。
- `occupancyEvents(externalNo)`：逐航段占用事件流（ACQUIRE / RELEASE，含版本与改道业务号）。
- `conflicts(externalNo)`：当前航线中时间窗内其他有效许可占用数已达到容量的冲突航段。

关闭：

- `get(closureNo)` / `list()`：关闭事件详情与全部事件（含状态、范围版本、区域航段）。
- `impacts(closureNo)`：某关闭事件下的受影响航班与逐航段结果（PENDING / REROUTED、
  标记时范围版本、处理改道号与时间）。
- `impactsForFlight(externalNo)`：某航班当前挂在哪些关闭事件下及处理结果。

## 测试

- `RerouteServiceTests` 覆盖：改道成功换线与容量转移、幂等回放与冲突、容量不足 / 版本过期
  时的回滚不变性、已取消与已完成许可的改道拒绝、已飞航段保护与旧位置请求不释放容量、
  高度与生效时间校验、历史版本与占用事件记录、冲突航段查询，以及并发改道只成功一次、
  改道与取消并发下最终状态一致。
- `ClosureServiceTests` 覆盖：仅标记尚未进入的航段（时间窗 / 已飞航段过滤）、
  关闭驱动改道的同事务新旧容量切换与 REROUTED 结果、替代航线穿越关闭区被拒、
  提交穿越关闭区被拒、范围版本过期 / 关闭取消 / 航班不再受影响 / 许可版本过期等旧方案拒绝、
  飞入关闭区后限制解除、修订只重算 PENDING 且保留已完成改道、取消只解除未处理限制、
  并发改道下容量约束（只成功一个）、改道与关闭取消并发的最终一致性，以及关闭事件 /
  受影响航班 / 处理结果的查询。
